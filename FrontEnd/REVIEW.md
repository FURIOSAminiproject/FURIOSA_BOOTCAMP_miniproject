## 2026-10-28 추가: 복수 취향 선택과 숙박 0건 안내

취향 카드를 한 번 누른 뒤에도 같은 단계에서 추가 선택·직접 입력을 받고, 선택 완료 버튼을 눌러야 요약으로 이동한다. 취향 텍스트와 분류 ID는 누적·중복 제거한다. 예전 브라우저 저장 대화가 요약 단계였다면 새 완료 조건에 맞춰 취향 단계로 복원하고 완료 버튼을 다시 표시한다. 숙박은 취향 분류와 독립 조회이며, 0건·조회 실패 화면에 중복 경고 대신 도착지 숙박 지도 검색 링크를 표시한다. 외부 지도 결과는 실제 DB 후보나 예약 가능 여부로 간주하지 않는다.

숙박 후보 카드는 도착지에서의 직선거리를 표시한다. 서버가 가까운 DB, 관광공사 실시간 20km, 먼 DB 후보 순으로 찾아 오므로 취향 카테고리를 선택하지 않아도 숙박 결과가 나올 수 있다. 실제 후보가 한 곳도 없을 때만 빈 상태를 표시한다.

## 2026-10-28 추가: 필수 대화 단계 보장·초기화·날짜별 도착지 여행

출발·도착지와 임의의 userText만 있으면 완료되던 조건, 모델의 step/isReady를 그대로 적용하던 조건과 저장 복원 시 완료를 추측하던 조건을 제거했다. 이동 수단은 미확정으로 시작하고 직접 확인한 자동차/도보와 취향 답변이 있어야 5단계다. 기간 답변을 취향으로 저장하지 않으며, 모호한 답변·대중교통을 자동차로 대체하지 않는다. 단계별 로컬 폴백도 같은 조건을 사용한다. 자동 생성 타이머를 제거하고 요약 후 명시적 생성 버튼을 사용한다.

입력창 옆에 초기화를 추가해 헤더가 화면 밖이어도 사용할 수 있게 했다. 초기화·화면 이탈은 진행 중 요청을 취소하고 늦은 응답을 무시한다. 저장 키는 v3이며 날짜 계산도 시간대에 독립적으로 수정했다. 버튼 클릭 이벤트를 여행 초안으로 잘못 받던 오류, 경로 duration/distance 필드 오류, 결과의 출발·도착 이름/주소가 누락되던 요청 스냅샷도 수정했다.

지도/채팅의 생성 흐름은 trip-planning.ts로 공유한다. 새 API의 도착 후 일정은 1~10일의 각 날짜와 첫날 도착 시각을 반영하며 관광·식사·카페·숙박 후보를 표시한다. 추천 장소 버튼은 경로 주변 목록에 없던 장소도 지도에 안전한 텍스트 팝업으로 표시한다. 식사 추천의 포함 여부와 지정 시간을 유지한다. 영구 일정 저장·예약·실측 도로 시간·영업시간 확인은 추가하지 않았다.

Node 22에서 타입 검사·상태/대화 테스트·production 빌드를 확인한다. 실제 브라우저는 외부 AI·DB·경로 제공자를 대역으로 바꾼 로컬 검증 서버에서 단계별 문답, 모호한 이동 답변, 요약 후 버튼 실행, 날짜별 서로 다른 장소, 저장 복원 및 초기화를 확인했다. 운영 API·DB·배포 성공과 구분한다. 아래 과거 F01~F06을 모두 해결한 변경은 아니다.

## 확인된 개선 항목

### F01 · P1 · 모델 응답 문자열을 Leaflet 팝업 HTML에 그대로 넣는다

- 근거: [TravelMapView.tsx](v1/src/components/TravelMapView.tsx)의 popupHtml에 place.name/categoryLabel/timeSlot/description을 직접 보간한 뒤 bindPopup에 전달한다. 설치된 Leaflet의 `src/layer/DivOverlay.js`는 문자열 콘텐츠를 innerHTML에 할당한다.
- 검증: Leaflet을 스텁으로 대체하고 장소 이름에 `<img src=x onerror="window.marker=1">`을 넣자 해당 문자열이 그대로 bindPopup 인수에 도달했다. 실제 DOM 삽입이나 스크립트 실행은 수행하지 않았다.
- 발생 조건·영향: 생성된 일정에 HTML/이벤트 속성이 포함되고 사용자가 팝업을 열면 HTML 주입과 스크립트 실행으로 이어질 수 있는 경로다. 실제 악성 모델 응답·운영 공격을 관측한 것은 아니다. 서버도 AI 응답 구조를 검증하지 않는다.
- 개선 방향: 장소 텍스트는 DOM textContent 등 텍스트 경로로 넣고 필요한 마크업만 안전하게 구성한다. HTML이 필요하면 신뢰할 수 없는 값을 정제한다. [백엔드 B01](../BackEnd/REVIEW.md)과 함께 검증한다.

## 2026-10-26 · 모바일 현재 위치와 ORS 경로 연결

- 대상: 원본 프로젝트 `FrontEnd/v1`. 브라우저 위치 측정, 경로 HTTP, 응답 검증, 화면, Leaflet 레이어를 분리했다. 기존 NestJS `POST /api/routes`를 사용하며 DB 구조·서버 인증·ORS 제공자 설정은 바꾸지 않았다.

- OSM Standard 스타일 원본을 확인해 도로/건물/상업지역/녹지/물/보행로의 대표 표기를 작성했다. 노란색을 교량 의미로 사용하지 않으며, 범례를 통행 가능 여부의 보증으로 설명하지 않는다.
- Node 22 타입 검사·여행 상태/분류 테스트 11개·운영 빌드 통과. 기존 Vite 설정의 향후 `__dirname` 호환성과 큰 JS 청크 경고는 남아 있다.
- 실제 React DOM/Leaflet 브라우저 검증 6개를 1280px와 390px에서 통과했다. 지도와 범례 색상 일치, 범례 접기/펼치기 중 기존 경로 유지, 경로 실패/선택 변경에 따른 항목 갱신, 입력 미리보기 상태, 가로 넘침을 확인했다. Enter 키로 접기/펼치기도 확인했다. 경로·장소는 모의 데이터, 외부 타일만 빈 레이어로 대체한 검증이다. 실제 휴대폰·운영 배포·전체 OSM 지물 검증과 구분한다.
- 검증 코드와 서버는 저장소 밖에 두었다. 실제 API와 DB 스키마는 변경하지 않았다. 사용법·출처는 [지도 범례 안내](docs/MAP_LEGEND.md)에 정리했다.

## 2026-10-28 실제 기상 모델 연결 수정

여행 결과와 날씨 미리보기의 하드코딩 기후표·날짜 해시·가상 관측·가상 신뢰도 생성 코드를 제거했습니다. FastAPI POST /api/v1/weather/predict/request로 도착지 좌표와 선택한 실제 날짜를 보내며 응답의 5개 모델 지표(TA_AVG/TA_MIN/TA_MAX/RN_DAY/WS_AVG)를 날짜별로 검증합니다. 요청 기간 외 날짜·누락·중복·비수치·물리적으로 유효하지 않은 값은 표시하지 않습니다.

화면은 평균/최저/최고 기온·일 강수량(mm)·평균 풍속만 보여줍니다. 강수량을 강수확률로 변환하지 않고, 미제공 습도·UV·신뢰도·과거 편차는 표시하지 않습니다. 모델 지역을 표시해 목적지 자체의 관측과 구분합니다. 예측 실패는 오류와 재시도를 제공하며 예시값으로 대체하지 않습니다. 기존 localStorage 날씨 캐시는 읽지 않고, 검증된 실제 응답만 좌표·기간별 메모리에 최대 5분 보관합니다. 조건 변경·언마운트 시 요청을 취소하며 이전 조건의 응답을 표시하지 않습니다.

로컬 Vite /fastapi 프록시는 FASTAPI_URL(기본 http://127.0.0.1:8000)을 사용하고 접두사를 제거합니다. 운영 Nginx는 기존 동일 경로를 사용합니다. FastAPI에는 DB의 해당 지역 모델 아티팩트와 WEATHER_PROJECT_DIR/데이터셋 준비가 필요하며 연결 코드 수정만으로 모델 배포가 보장되지는 않습니다.

검증: Node 22.23.3에서 상태/날씨 계약 테스트 21건, 타입 검사, production 빌드 통과. 실제 컴포넌트를 사용하는 격리 브라우저 화면에서 정상 응답(모킹), 서버 500 시 기존 수치 제거·오류/재시도, 목적지 변경 후 새 응답 표시를 확인했습니다. 원격 모델·DB·Gemini·운영 배포는 실행하지 않았습니다.
