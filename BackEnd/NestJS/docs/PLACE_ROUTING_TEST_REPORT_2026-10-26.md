# 장소 수집·ORS 경로 심화 검증 결과

검증일: 2026-10-26. 원본 프로젝트 `BackEnd/NestJS`, 커밋 `0602002`를 기준으로 검사하고 발견한 오류를 수정했다. 아래 최종 결과는 해당 커밋 이후의 수정 소스를 포함한다. 원격 DB·실제 제공자 API·AWS 배포를 실행한 결과는 아니다.

## 발견한 문제와 수정

| 문제 | 수정 전 재현 | 수정 후 |
|---|---|---|
| TourAPI 일부 항목 누락을 완료로 처리 | 전체 50건, 요청 100건, 응답 1건이어도 마지막 페이지로 판정할 수 있었음 | 요청 크기·페이지 번호·전체 건수로 예상 행 수를 계산하고 누락/초과 응답은 INCOMPLETE_PAGE로 중단 |
| 잘못된 수동 조건으로 수집 시작 | 소수 페이지·없는 상세 ID·날짜 오류·지원하지 않는 타입 등이 실행 단계까지 전달됨. 0/false 필터는 사라져 수집 범위가 넓어질 수 있었음 | 모드·날짜·조합·안전한 정수·본문/필터 자료형·알 수 없는 필드를 API 생성 전에 검증 |
| POST /run에서 일부 조건 무시 | `{ "region": "26" }`, detail/reference 모드만 보낸 요청이 일일 전체 증분 수집으로 분기됨 | 비어 있지 않은 본문이면 그 조건으로 수동 실행. 본문 없음/빈 객체만 일일 증분 실행 |
| 복합 요금을 단일 가격으로 확정 | “성인 5,000원 / 어린이 무료”를 amount=5000으로 확정 | 원문은 유지하되 유료·무료 조건이 섞이면 amount=null |
| 불완전 ORS 캐시를 정상 반환 | timeSpans=[]인 캐시를 거리·시간 검증에서 허용 | 현재 instructions=true 계약에 맞춰 최소 한 개의 구간을 필수로 확인 |

추가로 날짜 비교에서 Date를 일반 문자열로 바꾸며 밀리초를 잃을 수 있는 부분을 ISO 변환으로 정리하고 잘못된 객체 자료형을 거절했다. URL 인증 필드 제거에서 키 복사는 삭제 중 순회 누락을 막는 의도된 동작이므로 유지하고 이유를 설명했다.

불완전 페이지 검사는 HTTP 클라이언트와 수집 조율 서비스에서 공통 `tour-pagination.ts`를 사용한다. 다른 PageReader 구현으로 교체해도 실제 저장 전에 누락을 잡는다. CLI·HTTP·직접 호출은 `assertIngestionOptions` 검증을 공유하되 각 진입점의 기본값은 유지한다.

수동 HTTP의 실패 응답은 기존 결과 형식에 맞춰 HTTP 200 안의 `status="failed"`, `reason="INVALID_INGESTION_OPTIONS"`로 반환한다. 호출자는 HTTP 상태만 보지 말고 본문의 status도 확인해야 한다. 잘못된 입력 원문은 오류 응답·로그에 복사하지 않는다. POST 초기 수집의 배열 본문이 전체 초기 수집으로 바뀌지 않도록 확인했고, 잘못된 GET 쿼리도 실행 전에 실패함을 확인했다.

## 주요 검증 내용

- **TourAPI:** 키 별칭·1회 디코딩·출처 인증정보 제거, 단건/빈 목록 정규화, 페이지 번호 불일치, 누락·초과 항목, 101개 항목 두 페이지 수집, 5xx 단일 재시도, 인증/연결 오류와 요청 예산.
- **수동/배치:** 기본값·정상 문자열 변환·상하한 보정 유지, 잘못된 입력 시 API 서비스 미생성, 실패 후 실행 플래그 해제, 범위별 성공 날짜·실패 시 기준 유지, 실제 Nest HTTP의 POST/GET·조건 병합·잘못된 본문 거절.
- **변환:** 좌표 순서·누락값 보존, 윤년·한국 시각 변환, 분류 계층·코드 충돌, 단일/범위/혼합/무료/숙박 0원 구분, URL의 연속·중복 인증 필드 제거, 날짜 밀리초 비교.
- **실제 SQL:** 임시 PGlite에서 장소·분류·리뷰 FK, UUID 유지, 동일 내용 재수집, 상세 설명 보존, 비활성/재활성화 후 후기 유지, FK 실패 롤백 후 정상 재시도, 분류 부모 연결.
- **ORS:** 자동차/도보·선호도·역방향 캐시 분리, 좌표/JSON 경계값, 잘못된 구간·합계 시간·비어 있는 구간 거절, DB 캐시 손상·조회/저장 실패 처리.
- **동시성과 만료:** 같은 요청 100개를 한 번의 제공자 조회로 합침, 만료 1ms 전 재사용, 정확한 만료 시각에 재조회, 제공자 실패 시 오래된 결과 미반환, 재시도 성공과 기존 캐시 UUID 유지.
- **HTTP 제한 시간:** 로컬 HTTP 서버가 응답 헤더만 보내고 본문을 멈췄을 때 실제 fetch 취소와 PROVIDER_TIMEOUT 확인. 제공자 호출 한도·경로 계산 오류의 안전한 분류 확인.

## 확인 범위와 남은 운영 확인

제공자 응답은 고정 JSON/모킹 전송기 또는 로컬 HTTP 서버다. 실제 TourAPI·ORS의 현재 응답, 호출 한도·인증키·해외망 접속·서비스 가용성을 확인한 결과가 아니다. SQL은 PGlite에서 실행했으며 운영 PostgreSQL의 계정 권한·TLS·동시 세션 advisory lock은 실제 환경에서 따로 확인해야 한다. 이번 검증으로 배포 환경이나 실제 DB가 변경되지는 않는다.

페이지 전체 건수가 조회 중 바뀌거나 제공자가 응답을 축약하면 이제 불완전 응답으로 중단한다. 잘못된 성공 날짜를 기록하는 대신 이전 기준을 유지하고 다음 수집에서 재시도하는 정책이다.

관리자용 수동 수집 주소의 인증·역할 제한은 기존과 같이 아직 없다. 이번 로컬 HTTP 검증도 익명 요청이 실행기에 도달함을 확인했다. 운영 접근 제한은 별도 보강 대상이며 이번 데이터 정합성 수정으로 해결됐다고 표시하지 않는다. 기존 여행 AI·사용자 ID 타입 등 다른 모듈의 미해결 사항도 범위에 포함하지 않았다.

검증 전용 코드는 사용자 결정에 따라 저장소 밖에 보관했다. 배포 프로젝트의 `npm test`에 추가 112개 검증이 포함되는 것은 아니다. 새 검증의 실행·결과 로그는 이번 작업의 외부 검증 디렉터리에 남겼으며 보고서만 배포 문서에 포함한다.
